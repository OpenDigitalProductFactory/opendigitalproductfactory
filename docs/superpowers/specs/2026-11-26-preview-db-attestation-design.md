# Attest the database of a leased Contributor preview

BI-5C193A3F. First in the S5 preview dependency stack. This change supplies read-only proof, not enrollment, draft provisioning or activation.

**OBJ-1:** The lease owner can attest the exact dedicated database used by the current Contributor preview, and the consumer can match it on the transaction that would write.

| Acceptance | Objective | Statement |
| --- | --- | --- |
| AC-1 | OBJ-1 | A current lease owner records the database identity from the dedicated preview, bound to the exact lease, runtime and source revision. |
| AC-2 | OBJ-1 | The transaction rejects a different cluster with an identically named database, a different database on the same cluster, unreadable proof, or missing, expired, revoked or replaced owner provenance. |
| AC-3 | OBJ-1 | Production and unattested installations cannot use the proof as authorization. No production database, credentials or new privileged database role is involved. |

## Design

The authenticated lease owner reuses the existing TaskRun binding in `environment-lease-provenance.ts`. The host adapter in `scripts/lib/dev-preview-runtime.mjs` already uses Docker inspect and exec and discovers the protected canonical postgres service. Extend it to inspect the exact dev-postgres container and its mounted Compose `dev_pgdata` volume, then execute a read-only PostgreSQL catalog probe inside that container over its local socket as the existing PostgreSQL 16 `dpf` bootstrap superuser. Never use the consumer's DSN. Bind the inspected container ID, exact volume name, lease and immutable runtime/source revision to the resulting tuple. The existing check for the hostname dev-postgres is only a configuration check. The live-DB override demonstrates why it cannot establish the consumer connection.

Obtain the lease-owning production cluster's control identity through the same existing host boundary, identifying the canonical protected postgres container separately from dev-postgres. The host runner has the inspect/exec capability and already discovers that container, but there is no current control-identity probe. Require the already-authorized read-only local control-data path on that owner host. No credential handling, grants, or production probing during development or verification. If access is unavailable, ambiguous, or unauthorized the owner holds. Reject equal production and preview system identifiers before publishing even if all other metadata looks correct. The consumer independently rejects equality with the bound production identifier and holds if either identifier is absent. Cluster identity matters because both installations may name the database dpf and have the same catalog OID.

Use the sanitized-clone readback pattern with PostgreSQL's system identifier, current database OID and name, and postmaster start time. Fully qualify catalog relations and calls, including `pg_catalog.pg_control_system()`, `pg_catalog.current_database()` and `pg_catalog.pg_postmaster_start_time()`. Serialize identifiers exactly and use a canonical start-time representation without losing subsecond precision. A postmaster restart changes the time and an independently initialized replacement volume gets a new system identifier. Both invalidate the previous proof. Physical copies can preserve identifiers, so the tuple does not replace inspection of the dedicated runtime and storage. It establishes identity, not data freshness or unused contents. Restore fencing and one-shot accounting stay with BI-60FC9291 and BI-588688A7.

After the host probe, revalidate the exact active lease/runtime under the owner environment lock before publishing. Store the versioned proof only in `TaskRun.progressPayload.nonprodPreviewDatabaseAttestation`, with this layer as its sole writer. Merge into the current payload with a compare-and-set so concurrent wait progress cannot be lost. `checkpointNonprodLeaseWait` and other durable-wait updates preserve sibling keys via `waitPayload`; verify preservation on replay and on all applicable update paths. New admission must not copy old proof. Keep the existing `nonprodPreviewOwner.schemaVersion` at 1, owned by the lease provenance contract. BI-8EA98961 must not share this DB-proof version or overwrite this key.

Fetch the expected proof from the authenticated owner before opening the preview transaction. No network I/O under an owner lock or a preview write lock. The helper in `preview-db-attestation.ts` compares on the transaction-scoped client that would perform the write and refuses the root pooled client. Neither a cached lease read nor the comparison proves lease currency at commit. That requires BI-60FC9291. This layer cannot authorize a setup call or register a setup surface. Authorization unconditionally holds until BI-8EA98961 supplies its verified non-production installation join. An injected class flag is not supported.

## File boundaries and sequence

This layer touches `apps/web/lib/nonprod/environment-lease-provenance.ts`, the preview database proof helper and focused tests, and the existing preview startup adapter `scripts/lib/dev-preview-runtime.mjs`. The shared stack boundary is `environment-lease-provenance.ts`, `preview-runtime-fence.ts` and `environment-lease.ts`. The latter two remain unchanged in this layer unless the governed scope is amended. Stack BI-8EA98961 after this layer for the installation join, then BI-60FC9291 for reservation and release ordering.

## Research

The pin sources and downstream sequencing are in the [S5 provisioner design](2026-11-25-s5-rehearsal-draft-provisioner-design.md). The existing sanitized-clone probe reads network endpoint and database name, which cannot distinguish two clusters behind the same endpoint at different times. PostgreSQL documents the stronger available fields in [control file functions](https://www.postgresql.org/docs/16/functions-info.html) and [the shared database catalog](https://www.postgresql.org/docs/16/catalog-pg-database.html). PostgreSQL 16 does not revoke public execute on this function in its [initdb ACL script](https://raw.githubusercontent.com/postgres/postgres/REL_16_STABLE/src/backend/catalog/system_functions.sql). The preview uses its existing bootstrap superuser, not a new database role. Verify actual privileges and the probe in disposable PostgreSQL.
