## Proposed contract boundaries

1. **Task requirements, not missing fields, decide source need.** Resolve source
   requirements from the existing registered work-shape/stage and assignment
   contracts. Null source fields alone do not make a room source-free, and prose
   or a caller flag grants nothing. First inspect whether the QA room was given
   the wrong stage/shape rather than inventing another Workroom kind or schema.
   If existing typed requirements cannot express the task, return that precise
   design gap for governed sizing; do not silently exempt all blocked rooms.
2. **Initial binding differs from transfer.** Reuse the delivered canonical
   room-authority contract in bounded-handoff-authority.ts and the selected
   authority contract in the bounded-handoffs design. The authenticated human
   and already admitted canonical assistant may endorse an external executor
   locator; that endorsement does not authenticate a physical chat, grant a
   permission or establish independent-review identity. Do not require a new
   external-session registry or turn a supplied locator into an actor credential.
   An initial binding requires an actually admitted current assignment, matching
   owner and canonical assistant/surface, a current authorized connection and
   room action access. A missing assignment is an accountable pre-effect hold;
   null fields and matching principal alone do not establish the assignment.
   Reuse current command receipts and serialized compare-and-set. Recheck
   assignment, canonical actor access, delegation, room lease incarnation and
   any actual task execution fence inside the final write transaction. Keep
   the canonical environment/room/authority lock order and existing bounded
   lease, Build Studio and policy-evidence dependency fences. An endorsement
   cannot transfer an existing lease, invalidate an exemption or assume unknown
   original effects are settled. Missing/ambiguous dependency evidence holds.
   A concurrent non-null executor refuses the initial write. A genuinely changed
   non-null assignment follows the existing source-request/real-receiver-ACK
   contract. No initial binding rewrites the original failed approval or its
   evidence. Historical absent thread attribution remains absent.
3. **Historical evidence is read, never re-executed.** Consolidate bounded
   original evidence selection in its existing module. Preserve raw arguments
   and results server-side. If authentic stored evidence cannot establish the
   original result, expose a precise unavailable reason and accountable owner;
   do not manufacture a proof, infer settlement from inactivity, or broaden the
   known-refusal allowlist to make this occurrence eligible.
   Keep reads bounded by the existing exact-envelope selector and its LIMIT+1
   overflow detection in approval-action-evidence.ts, and the two-candidate
   ambiguity check and PACKET_MAX_BYTES in the failed-handoff recovery reader.
   Reuse their constants; do not raise or copy them into another policy. Overflow
   or unknown attempt coverage remains unavailable. No inventory-wide scan is
   a recovery proof; any later indexed expansion belongs to EP-WORK-CONVERGENCE.
4. **Projection follows actual eligibility.** Reuse existing recovery projections
   and governed actions. Explain task kind, binding status, next owner and
   missing proof on the surface. Keep opaque identifiers under diagnostics;
   disclose detailed lineage progressively. Navigation and status reads have
   no execution effects. Do not add a second status ledger or retry scheduler.

## Strict initial-assignment adapter

The existing create_workroom tool accepts an optional sessionRef for a NEW
external acceptance assignment. Its initial-workroom-assignment.ts adapter is
restricted to the current registered acceptance-verification definition and the
existing canonical external assistant/surface mapping. A locator is endorsed
data, never a credential or proof of review independence. Calls without this
field retain the existing creation path. Native task/fence contexts, unsupported
surfaces, restricted work and missing current connection proof return a bounded
accountable hold; they are not made external to fit this adapter.

One real Read Committed transaction takes the existing canonical environment
locks, serializes the idempotency key, revalidates current OAuth/human/grant
intersection, creates the room and canonical WorkItem anchor, and establishes
its actual owner and assistant admission. The same transaction records the existing
acceptance-verifier role binding for that authenticated assistant. Each declared
verification write and creation must be reachable through both current persisted
agent grants and token scopes; alternatives within each tool retain the canonical
OR semantics. A role binding grants no authority or review independence.
It then checks the current exact room,
canonical principals, owned lease and existing bounded lease/build/exemption
dependencies before the final connection and room recheck. Canonical anchor
ports accept that same transaction client. No global database fallback is used
for these writes, and no fabricated old executor is passed as a transfer actor.
The dependency reader deduplicates the single actual endorsed destination.

The initial action record and room/anchor/participant writes commit together.
Notifications run only after commit and remain best effort. A notification
failure cannot turn a known committed assignment into an uncertain retry.
Creation input/argument types live with the existing store contracts rather
than growing the baselined store module.

A duplicate request can only read one matching accepted initial assignment with
its original owner, assistant, kind, locator, scope and action evidence. An old
null executor, changed non-null assignment, changed actor or missing/ambiguous
initial evidence stays held. The strict path never late-binds a legacy room or
replays its failed approval. A genuine uniqueness race first rolls back the
outer transaction, then performs one fresh winner reconciliation without
creating again. The store must not query a winner on an aborted caller-owned
transaction.

Source-local adapter/dispatch and existing boundary suites pass; these qualified
identity fixtures do not attest live identity or acceptance. The six PostgreSQL
cases cover concurrent duplicates, complete rollback, both observed lock orders
against the actual lease allocator, an actual legacy uniqueness winner, and
verification-target separation from the actual source-author relation.
They require an admitted disposable database and remain UNRUN until executed
there. Final exact-tree qualification, independent review, protected publication
and containing-runtime acceptance remain required.

The general MCP tool-pack architecture page still describes the same pack
composition, handler/grant ownership, consequence declaration and governed
execution path. This adds no pack, tool, grant, authority scope or parallel
executor. The field, strict transaction and compatibility limits belong here
and in the existing tool definition; record that precise not-affected
architecture-page disposition through the current documentation-impact writer.

## Verification target is separate from source authorship

Like the existing acceptance-sweep producer, a source-free acceptance assignment
keeps the delivered item in outcomeAnchor and leaves backlogItemId null. The
latter is the source-author subject used by baseline and reviewer recovery.
Promoting the target into that column made a second active author room and
prevented resolution of the real source author. A pure actual-helper
counterexample and three first-failing adapter regressions reproduced this
before publication.

The strict adapter rejects an explicit authored backlogItemId, validates the
normalized target with the existing resolver, and locks that real target row
for the transaction. Its effective sensitivity uses the existing canonical
backlog policy; only public or internal targets use this narrow adapter.
Confidential and restricted targets retain their controlled assignment boundary
instead of inheriting a weaker room policy. Unknown or concurrently removed
targets stay held. Replay
retains current scope and target checks and never rewrites an old misbound room.
