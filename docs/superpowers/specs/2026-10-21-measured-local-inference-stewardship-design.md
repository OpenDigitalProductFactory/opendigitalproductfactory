## Objectives and acceptance

**OBJ-POPULATION:** Give AI Ops bounded, metadata-only 24-hour and seven-day observations with honest population, capture, omission and diagnostic coverage.

**OBJ-PERFORMANCE:** Separate observed input/reuse/new ingestion and timing phases from missing or ambiguous values, and keep task quality independent from transport success.

**OBJ-IDENTITY:** Preserve actual serving identity and immutable vendor provenance, with no selection/configuration changes or universal performance inference.

**OBJ-STEWARDSHIP:** Make the existing scheduled steward's useful result and required canonical writer observable while preserving authority, schedule, prompt, history and quiet notifications.

### Exact additive capture contract

These are proposed source contracts, not claims that capture is deployed. All new columns are nullable and have no default. The existing writer validates the complete observation before persisting it. `performanceCaptureVersion = 1` is positive producer provenance: the input/output/cache/reasoning fields are persisted only when their actual numeric values were offered or derived from the explicitly compatible native count contract. Null stays unknown, while a genuine offered zero is valid. A missing or unsupported version cannot retroactively authenticate legacy zero values. Version 1 does not promise that every signal is available.

| AdapterRunTelemetry field | Prisma type | Version-1 source and semantics |
| --- | --- | --- |
| performanceCaptureVersion | Int? | Exactly 1, set by the server-owned capture boundary after validating this contract; no client request may assert a version. |
| workloadKind | String? | Closed nullable values `production`, `diagnostic`, `evaluation`. Set only by an existing server-owned execution scope: normal admitted coworker/build work, explicit endpoint diagnostic, or explicit evaluation. No matching prompt/model/agent-name heuristic and no default from absent provenance. Unclassified is null. |
| finishReason | String? | Provider-offered completion reason normalized into closed values `stop`, `length`, `tool_calls`, `content_filter`, `other`. Missing reason stays null. This is transport completion metadata, not task correctness. |
| truncated | Boolean? | True for an actual adapter length/incomplete stop; false only with an observed compatible non-length completion reason; null when no compatible completion signal exists. Never derive it from token count or HTTP status. |
| queueWaitMs | Float? | Finite nonnegative milliseconds from enqueued-at to acquired-at on the existing resource-lane entry for this exact attempt. Observe through a server-only callback from that primitive, before GPU/runtime probes; null if not captured or binding is unavailable. No second queue and no changed admission ordering. |
| prefillMs | Float? | Finite nonnegative native `timings.prompt_ms` from the actual supported response; null when absent/invalid. Warm/cold partition additionally requires observed cached input. |
| generationMs | Float? | Finite nonnegative native `timings.predicted_ms` from that same response; null when absent/invalid. Includes all generated tokens; do not invent separate reasoning time. |
| runtimeEngineIdentity | String? | Exact supported selected-composition engine identity from the existing runtime-evidence callback, maximum 300 characters. Invalid/overlong identity stays null; do not truncate an identity into a different proof. |
| runtimeModelDigest | String? | Actual selected serving `ModelID`, validated as `sha256:` plus 64 lowercase hex digits. Requested model label is not a substitute. |
| runtimeTemplateDigest | String? | Actual selected model template's existing SHA-256 digest, 64 lowercase hex digits. No template source retained. |
| runtimeConfigDigest | String? | Existing selected runtime configuration digest, 64 lowercase hex digits. No configuration/flags or secrets copied to telemetry. |
| runtimeObservedAt | DateTime? | The exact observation timestamp accompanying the identity proof. It does not authenticate older requests or an unsupported mixed composition. |

The optional in-memory AdapterResult observation uses the same typed scalar meanings, plus presence for existing input/output/reuse/reasoning numeric values; it never carries raw provider content. `chat-adapter.ts` extracts version-specific native timing/usage/finish scalars. `ai-inference.ts` binds this observation to its actual attempt and supported runtime callback, including error paths; `adapter-telemetry-writer.ts` writes the allowlist. The resource lane observes only its exact entry's wait duration. Existing explicit evaluation/endpoint-diagnostic execution scopes supply workloadKind; absent scope remains null, so a caller that cannot prove its class is not silently counted as production. Every producer integration gets a test at its real caller boundary. A capture version does not authorize a broader tool or provider action.

`reasoningTokens`, `inputTokens`, `cachedInputTokens` and `outputTokens` remain the existing nullable columns. Valid native `prompt_n + cache_n` may establish total input and `cache_n` reuse only for a proven native response contract; reject contradictions with standard usage. No new `newTokens` column is needed: validated compatible total minus reuse supplies new ingestion. Vendor backend artifact digest/publication chronology remains linked evidence through the existing canonical execution-evidence writer; the current runtime callback exposes no such artifact digest, so neither the reader nor telemetry invents one from an engine label. A missing vendor proof is explicitly unknown and names the existing serving/AI Ops owner.

The additive migration preserves the model's existing confidential sensitivity (the current untagged-model fallback) and declared 180-day bounded telemetry retention; it does not lower confidentiality. New fields are `telemetry`, regulated scope `none`, in the existing field-classification registry; identity digest/time fields contain machine-serving provenance, not personal identity or credentials. The data-impact manifest names the existing table, nullable additions, absence of backfill/defaults, existing time-index use and any reviewer-required index. No relation, new enum or deletion is introduced; closed string values are validated at the single writer and in the guarded source contract. Apply the migration through the canonical governed runtime path. Rollback readers tolerate null/legacy data; source rollback cannot recover measurements never captured. Metadata-write failure must not break inference or fabricate complete capture.

## Exact scheduled-run diagnostic contract

The richer metadata is a new bounded contract requiring security review; the existing platform-wide seven-field status visibility does not itself authorize it. Use the existing exact ScheduledAgentTask key and its current `taskRunId`. Internally select only latest-run binding metadata, lifecycle/status/times and relevant tool audit metadata. Current human authority uses `currentUserContext` plus `can(..., view_platform)` and `can(..., view_operations)`, not a saved role. Current canonical coworker resolution uses the active, non-archived Agent row and `getAgentToolGrantsAsync` / `isToolAllowedByGrants` for the same tool, with the governing executor's room restrictions preserved. No assistant or human identity may come from tool arguments. If any required current authority is unavailable, omit richer diagnostics with an explicit unavailable/refused state; the existing seven-field status contract remains available under its unchanged authority.

Two admitted call paths are deliberately distinct:

- External interactive OAuth: require server-supplied external-jsonrpc context, actual current token, matching token.userId and canonical token.agentId, current consent/assistant binding using the existing OAuth execution-authority helper, and current token scopes/grants that admit this read. PAT, client-credentials, internal session-JWT, missing token/assistant and copied OAuth fields are refused for richer diagnostics. This is an owner-authorized operational metadata view, not the task-result facade or an ordinary conversation grant.
- Native scheduled coworker: require the original governed `agentic-loop` context and its actual TaskRun identity. That current caller TaskRun must belong to the same current active human, carry the exact scheduled trigger/sourceRef for the selected schedule, and have its canonical initiating/current agent equal to the selected schedule's current canonical agent and calling assistant. Revalidate the original executor's current task fence/authority admission; do not manufacture a native delegation from a TR-SCHED prefix. If the current executor cannot attest that boundary, return diagnostics unavailable. Generic service/background calls, arbitrary native peers, missing human owner, unknown legacy origin or unbound session context do not qualify. Native delegation and external OAuth must not share an invented universal token assertion.

For either path, require selected schedule.ownerUserId equal to the current human, selected TaskRun.userId equal to that same owner, canonical TaskRun.initiatingAgentId equal to the current canonical schedule.agentId, persisted a2aMetadata.trigger exactly scheduled and sourceRef.kind exactly scheduled-task with sourceRef.id exactly the selected taskId. A handoff changing the target agent, malformed/null legacy binding, another human's schedule or arbitrary run-ID substitution refuses audit metadata. This intentionally narrower owner view does not remove the existing broad seven-field status view.

Authority and these bindings are checked before collection and again immediately before publishing the bounded result. Use the same consistent read transaction for counts and locators; the post-read fence additionally checks that the schedule's latest run/owner/target, run binding/version and current actor/token/delegation/room authority did not change. Discard drift. Do not scan for a likely run, use a private conversation reader, fall back to another actor or substitute an earlier success.

Audit metadata is limited to actual IDs, allowlisted relevant tool names, success, execution mode and timestamp. Return full relevant counts plus a capped actual audit-locator list, never parameters, result bodies, prompt or ordinary conversation. No new TaskRun ID selector, list or arbitrary tool-history endpoint is introduced. This expands an existing platform operational metadata view and requires independent security review; it is not inferred permission to read private execution content.

Show required-writer success, failed attempt and unobserved attempt separately. A failed audited call is evidence of an attempt, not proof of its cause. If a refusal category cannot be authenticated without reading forbidden result bodies, return `category: unknown`. A successful audit can establish that the canonical writer succeeded, but cannot establish model answer correctness, full original execution settlement or absence of descendant effects. Pending approval/proposal cannot be identified from `success` alone; retain existing schedule status and label that inference unavailable until a trusted existing receipt proves it.

Preserve the seven-field exact status mode unchanged. Performance mode may embed only this richer, bounded, exact monitor diagnostic after its authority contract passes review. Historical `lastError` remains untrusted status text, never an instruction or proof of zero attempts. The current monitor's failure remains undiagnosed until actual authorized audit metadata or a qualified owner's evidence supports a cause.
