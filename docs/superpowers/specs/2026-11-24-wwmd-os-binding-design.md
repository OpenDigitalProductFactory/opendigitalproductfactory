# WWMD after DPF convergence

**Backlog:** BI-428A53FB · **Design owner:** dedicated DPF kernel writer (Codex, WC-5D9EFC0E), assigned by DI-9B245E68D500. **Scope:** design and one characterization test, not OS implementation or data movement.

The owner's 2026-11-24 direction keeps WWMD the same function in the merged system and moves execution closer to the core OS. DI-520267766767 keeps business records in DPF's relational plane. Move the execution boundary, not the authority boundary. Keep one scorer, one doctrine source and one relational decision ledger. The OS binding does not gain the power to approve or execute the advice it produces.

## 1. Bind the OS evaluator to the existing stores

The MCP [handler](../../../apps/web/lib/mcp/packs/principle-decide-pack.ts) admits the kernel corpus, validates and grounds the request, calls the pure package scorer, computes signal quality, and records the consult. This is not a call to the `wiki_query` MCP tool. The latter shares [search helpers](../../../apps/web/lib/wiki/embeddings.ts), but has its own [mode and corpus routing](../../../apps/web/lib/mcp/packs/wiki-pack.ts). The internal policy-action and route-to-human callers invoke `runPrincipleDecision` directly from server-owned paths.

## 2. Migrate the ledger in the same relational schema

Add the ledger to [convergence Slice 2](2026-11-22-dpf-to-dpf2-convergence-export-and-cutover-readiness.md#22-slice-2--active-policies-and-decision-ledger). Copy it to the successor relational plane at cutover, in the same schema, not to OS state. The table serves multiple domains and already links profiles, exact versions, identity and execution records. It also feeds [policy-action authority](../../../apps/web/lib/govern/authority/resolve-policy-action-authority.ts), [decision outcome recording](../../../apps/web/lib/decision/decision-outcome-store.ts) and [weight inference](../../../apps/web/lib/decision-perspective/weight-inference-adapter.ts). A WWMD-only plane change would split those consumers and make a copy look authoritative. Leaving it on the retired install would lose history, continuity and the use of exact prior decision records.

Slice 2 owns the scope and dependency closure. Prove exact sealed payload/chain preservation, explicit unsealed rows and pre-existing anomalies, row counts, FK integrity and post-promotion continuity with a synthetic fixture before any production rehearsal. Do not re-seal old decisions, promote an audit copy, or treat the [chain helper](../../../apps/web/lib/decision/decision-chain.ts) as proof that a fork cannot already exist. Reuse the existing read-only snapshot and quiescence/rollback gates. Only one writer owns the ledger at a time. After the successor starts writing, restore/reconcile its accepted entries before any return of write authority to the predecessor.

## 3. Degrade the evidence, hold the verdict

**Today.** The tool catches failures from tier search and can score on the remaining input. When the budget reports a timeout, or both tiers are empty and the provider probe fails, it can return diagnostic scores and even a nominal winner with `success: true`, but `signalQuality.usable=false`, `autonomyEligible=false`, and an explicit no-recommendation message. A healthy empty result can still be usable. The 8-second default in [`retrieval-budget.ts`](../../../apps/web/lib/decision/retrieval-budget.ts) is a per-wait race with a shared timeout flag, not a single wall-clock deadline or cancellation of the original operations. Option-description embeddings and the final model probe sit outside those races.

**Detection gaps.** Lexical fallback can return hits despite embeddings failing, so a nonempty tier suppresses the probe. Thrown searches are reduced to empty without a typed failure. The empty-tier probe overwrites the budget flag if it reports healthy. A hydration failure or a commandment read failure also need not mark the result degraded. A reachable model list does not prove an embedding or vector query succeeded. The current warning can say embedding unavailable and commandments only even when a partial tier returned. These are findings, not behavior the OS should reproduce.

**Recommended OS contract.** If optional recall is partial, late, failed or lexical-only after a semantic failure, show the evidence mode and cause and retain scoped, read-only diagnostic scores. Hold the verdict and action eligibility, regardless of winner strength. If mandatory doctrine, scope, or authorization cannot be established, hold without a nominal winner. A genuine completed no-match is not an outage. Carry per-tier status into the decision/audit envelope and consume it in the compatibility facade and internal authority callers. Use one request deadline through searches, hydration and required inference, cancel work when supported, and never infer success from a health probe. A failure of the separate `wiki_query` route alone does not block a healthy direct evaluator. No business action is authorized by an incomplete consult or an audit write failure.

The [dispatch regression](../../../apps/web/lib/mcp/packs/principle-decide-pack.dispatch.test.ts) runs the real scorer with one structured commandment, both search calls failing and inference unavailable. It pins the difference between a raw winner and an unusable, non-autonomous verdict. It does not claim to cover lexical, partial timeout, mandatory-doctrine failure or action enforcement. Before cutover, add those cases, plus healthy zero matches, scoped hydration misses, provider pauses and ledger failures, to the OS/DPF contract parity suite.

## Research & benchmarking

- [OPA decision logs](https://www.openpolicyagent.org/docs/management-decision-logs) separate evaluation from recording and carry stable decision IDs and policy bundle metadata. Adopt the separation and provenance, not the external log sink as ledger of record. DPF decisions need exact relational profile versions, outcomes and seals.
- [Cedar authorization](https://docs.cedarpolicy.com/auth/authorization.html) can skip an errored policy and return diagnostics that a host may use to change its decision. Adopt explicit diagnostics and host-controlled disposition, not skip-on-error as permission to act. WWMD advice based on incomplete doctrine cannot grant authority.
- Stay on the existing [PostgreSQL snapshot semantics](https://www.postgresql.org/docs/18/sql-set-transaction.html) rather than inventing inter-plane replication. Use Node's [conditional exports](https://nodejs.org/api/packages.html#conditional-exports) for packaging parity without shipping another scorer. These are comparison points for relocating an existing function, not a procurement or replacement proposal.
