1. Problem

A dispatch agent's value is emergent across many actors over time: one dispatcher, several technicians, many customers, and a day of real-world chaos — jobs running late, no-shows, parts missing, emergency reshuffles. Two test tiers exist today and neither proves this:

  • Pure unit tests (F0/F1/F2a) prove the decision atoms — fast and deterministic, but blind to emergent process.
  • Single-logged-in-user happy-path drives (e2e, dogfood) prove UI plumbing for one actor — they cannot represent a dispatcher coordinating independent technicians and customers.

The operator named the gap directly: "a dispatch agent would need to simulate real people with real dispatch processes and to test the process with real-world challenges and variants." The missing middle is a multi-actor, time-aware simulation harness plus a behavioral eval for the non-deterministic AI dispatcher. Without it, "functionally competitive" is unprovable.

2. Goals

  1. Multi-actor fidelity. Simulate a dispatcher plus N technicians and M customers as independent principals, not one user session.
  2. Domain-level driving. Actors exercise the same governed server actions/tools the real UI calls — not (primarily) the browser.
  3. Time control. A virtual clock advances time and fires temporal events (T-24h watch, ETA timers, SLA clocks) with no wall-clock waits.
  4. Real-world variants. A reproducible scenario library encoding the challenges (late, no-show, parts-out, emergency reshuffle, landline-only elder).
  5. Invariant oracles. Process invariants asserted across every scenario.
  6. Behavioral eval. Run the real LLM dispatcher against scenarios and score its decisions against the oracles and a rubric, tolerant of non-determinism.
  7. Reusable. The harness is coworker-agnostic; dispatch is the first proving vertical, as Build Studio was for the pseudo-user contract.
  8. No production coupling. Headless, against test substrate, with all external boundaries (comms, QuickBooks) stubbed — no real customer egress.

3. Research & benchmarking

The test pyramid for an AI agent that coordinates people has four tiers; this harness builds the two missing middle ones.

Reusable building blocks found (2026-06-14 sweep):

  • services/integration-test-harness/ — a scenario-driven mock vendor server (ADP, QuickBooks) with fixtures (happy-path, rate-limited, malformed, token-expired) flipped via a control endpoint. The right pattern for the external boundary; already covers QB.
  • Pseudo-User Contract — coworkers are delegated principals (Principal + PrincipalAlias). The identity model for "actors that are not the logged-in user" already exists; test actors extend it.
  • e2e/ Playwright + helpers — solid single-actor UI drive; reused only for the thin top smoke tier.
  • vi.useFakeTimers() — unit-level clock; the virtual clock generalizes it to scenario time.
  • The Field Dispatch units (@dpf/validators field-dispatch) are deliberately Date.now-free, so clock injection works with no rework.

Anti-pattern rejected: driving five concurrent Playwright browser contexts as the primary coverage. It is slow, flaky, and proves UI plumbing rather than dispatch logic. Browser multi-context is reserved for a handful of UI-smoke scenarios only.

5. Architecture decisions

ADR-1 — Simulate actors at the domain layer, not the browser

Actors invoke the same governed server actions/tools the UI calls. This exercises real dispatch logic, runs headless in vitest, and is deterministic. Multi-browser is a thin UI-smoke tier, not the coverage.

ADR-2 — Time is an injected dependency, never wall-clock

All temporal logic flows from a VirtualClock through a ClockPort. Scenarios advance time explicitly; no setTimeout waits. Modules under test must accept now (already true for F0/F1/F2a).

ADR-3 — Deterministic core, eval for the non-deterministic edge

The world, actors, and clock are seeded and reproducible (a regression net). The LLM dispatcher is wrapped by a separate eval that scores decisions across runs against the oracles and a rubric — non-determinism is handled by scoring + thresholds, not by asserting exact output.

ADR-4 — Two actor fidelities

Scripted responders (deterministic) for regression + oracle proofs; LLM persona-actors (a customer agent, a technician agent on the A2A substrate) for realistic, varied, adversarial behavior — the "simulate real people" fidelity that surfaces the unexpected.

ADR-5 — No external egress, ever

Every external boundary (SMS/WhatsApp/email send, QuickBooks write) resolves to a harness mock. A real customer message or QB write from a test run is a hard defect. Reuse the integration-test-harness control plane.

ADR-6 — Coworker-agnostic; dispatch first

The world/actor/clock/scenario/oracle/eval contracts are generic. Dispatch supplies the first world fixture, actor scripts, scenario library, and oracle set. Other coworkers reuse the contracts.

  }

6.2 Constraints

  constraint def C1_Reproducible { /* identical (worldSeed, scenarioId) => identical non-AI trace */ }
  constraint def C2_NoEgress     { /* comms + QB boundaries are mocks; real adapters are unregistered */ }
  constraint def C3_SameTools    { /* actor calls subset of production server actions / MCP tools */ }
  constraint def C4_ClockInjected{ /* no unit under test reads Date.now(); time flows from VirtualClock */ }

6.3 Structure (parts, ports, interfaces)

  port def ClockPort        { /* now() : Instant; advanceTo(t : Instant); fireDue() */ }
  port def DomainActionPort { /* the governed dispatch actions/tools an actor may invoke */ }
  port def CommsBoundaryPort { /* stubbed send + recordDeliveryAttempt; scenario-controllable outcomes */ }
  port def ObservationPort   { /* read-only: jobs, statuses, notifications, delivery attempts, invoices */ }

  interface def ActorToDomain { end actor : DomainActionPort; end system : DomainActionPort; }

  part def VirtualClock      { port clock : ClockPort; }

  part def DispatchSimWorld {
    // the synthetic world — seeded rows on existing models, one tenant
    part fleet        : Vehicle[1..*];
    part technicians  : TechnicianActor[1..*];
    part customers    : CustomerActor[1..*];
    part jobs         : FieldServiceJob[*];      // WorkItem sourceType = field-service-job
    part bindings     : ChannelBinding[*];        // verified comms channels per customer
    ref part clock     : VirtualClock;
  }

  part def ActorRuntime {
    // drives actors turn-by-turn against the domain, advancing the clock
    port domain : DomainActionPort;
    port clock  : ClockPort;
    part dispatcher : DispatcherUnderTest;  // the AI coworker, or a deterministic reference stub
  }

  part def TechnicianActor { /* scripted or LLM: depart, arrive, run-long, report-parts-missing, complete */ }
  part def CustomerActor   { /* scripted or LLM: confirm, ignore, reschedule, not-home */ }
  part def DispatcherUnderTest { /* binds to the seeded Dispatcher coworker (F2b) or a reference policy */ }

  part def ScenarioRunner {
    part world   : DispatchSimWorld;
    part runtime : ActorRuntime;
    part oracles : OracleSet;
    port observe : ObservationPort;
  }

  part def OracleSet      { /* the invariants asserted after a run (see §7.2) */ }
  part def ExternalBoundaryMocks { port comms : CommsBoundaryPort; /* + QB via integration-test-harness */ }
  part def EvalHarness {
    // wraps ScenarioRunner with the real LLM dispatcher and a scoring rubric
    part runner : ScenarioRunner;
    part rubric : EvalRubric;
  }
  part def EvalRubric     { /* weighted criteria scored per scenario run (see §8) */ }

6.5 Mobile field-signal contract & geo-temporal model

The routing inputs a dispatcher depends on — technician location, departure, arrival, and ETA — originate on the technician's mobile device in production. The harness simulates them as the same signal contract the real app emits, driven by a deterministic geo-temporal model. The stub is therefore the convergence point with the separate mobile-app design thread: functional parity means both honor one MobileFieldSignal schema (location | departed | arrived | eta | status) and the same geofence/ETA semantics. 

  requirement def R11_MobileFieldSignalContract {
    doc /* Routing sensors and status updates (location, departed, arrived, ETA)
            enter the system through one mobile field-device signal schema. The
            harness stub and the real mobile app emit the same schema. */
  }
  requirement def R12_GeoTemporalSimulation {
    doc /* The harness shall simulate realistic geography (positions, routes,
            distances, traffic-adjusted travel time) and time-of-day effects so
            routing, ETA, on-my-way, and running-late run under realistic
            geo + temporal situations. */
  }

  port def MobileFieldDevicePort {
    // emits MobileFieldSignal = location | departed | arrived | eta | status
    // implemented by BOTH the real mobile app and the SimulatedMobileDevice stub
  }
  part def GeoTemporalModel {
    // geoDistanceKm, travelTimeMinutes(traffic), etaAt, positionAt,
    // withinGeofence, trafficFactorForHour — deterministic, clock-driven
  }
  part def SimulatedMobileDevice {
    port device : MobileFieldDevicePort;
    ref part geo : GeoTemporalModel;
    // planDrive(from, site, departAt) -> deterministic MobileFieldSignal timeline
  }

  connection techToDevice connect TechnicianActor to SimulatedMobileDevice.device;
  allocation a7 allocate MobileFieldDevicePort to mobileApp.fieldSignalContract; // convergence target
  allocation a8 allocate GeoTemporalModel      to harness.geoTemporal;

  satisfy R11 by MobileFieldDevicePort;  satisfy R12 by GeoTemporalModel;
  verify R11 by VC6_MobileSignalParity;  verify R12 by VC6_MobileSignalParity;
  verification case def VC6_MobileSignalParity {
    objective /* the stub emits the MobileFieldSignal schema; geo distance/ETA/geofence
                 math is deterministic; running-late derives from ETA vs. window */
  }

Convergence contract. The mobile-app thread implements MobileFieldDevicePort from real GPS and taps; this harness implements it from planDrive over the geo-temporal model. Both are verified against the same MobileFieldSignal schema, so scenarios written here transfer to the real device, and the device's routing behavior is testable here before it ships. Built & verified (21/21): packages/coworker-sim-harness/src/geo-temporal.ts + mobile-signals.ts.

7.2 Invariant oracles (R5)

  constraint def O1_CustomerInformed   { /* every job with a verified channel is notified before/at its visit */ }
  constraint def O2_NoDoubleBooking    { /* no technician assigned two overlapping on-site windows */ }
  constraint def O3_LateCascadeFires   { /* a job overrun by > threshold triggers downstream re-notification */ }
  constraint def O4_CompletionInvoiced { /* every job reaching complete yields exactly one DPF Invoice (sourceType=field-service-job) */ }
  constraint def O5_FailuresSurface    { /* every failed delivery becomes a board exception */ }
  constraint def O6_EmergencySla       { /* an emergency is assigned and customer-notified within the SLA window */ }
  constraint def O7_NoPhantomState     { /* no completion/invoice without an on-site arrival */ }

8. Behavioral eval rubric (R7)

The deterministic oracles are pass/fail invariants. The eval scores the quality of the LLM dispatcher's decisions across N runs per scenario, so regressions in judgment are caught even when invariants still pass.

CriterionSignalWeight
Invariant adherenceO1–O7 pass rate across runs0.40 (gate: must pass)
Timelinessnotification/assignment latency vs. ideal0.20
Reassignment qualityskill+proximity+value fit of reshuffles (vs. reference)0.20
Customer-experienceredundant/again-failed notifications minimized0.10
No harmful actionzero unapproved customer sends; zero out-of-policy writes0.10 (gate: must be zero)

Scored over multiple runs with a pass threshold; this is the routing-eval pattern applied to dispatch — and the regression net that keeps the AI dispatcher measurably better than incumbents as it evolves.

13. Recommended next step

Build H0 now — the VirtualClock and the synthetic-world seed — since it has no dependency and the field-dispatch units are already clock-injectable. In parallel, continue F2b (the Dispatcher coworker + its server actions); H1 binds to those actions to light up the first end-to-end scenario suite. The dispatcher remains the critical first functionality; this harness is what proves it works.
