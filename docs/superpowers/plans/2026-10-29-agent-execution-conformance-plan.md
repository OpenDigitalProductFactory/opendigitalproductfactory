# Agent execution reliability: phased convergence plan

**Planning owner:** BI-1FDAA62B / WC-C44D18D5. **Design:** [Complete the agent execution journey](../specs/2026-10-29-agent-execution-conformance-design.md). **Decision:** DI-6A05E518B86D (design direction, not implementation/review approval).

## Delivery shape and operating rule

This is a decomposed cross-domain program using existing BIs and their active owners. The research/documentation phase may publish independently. Runtime implementation remains with admitted child Workrooms and approved scope. No new engine, session store, service, model subscription or blanket permission. The plan adds one missing executable conformance deliverable, BI-7DC3B91D; it does not clone existing repair work.

Fix the shortest complete development loop first. Limit the critical-path execution changes to one admitted slice per affected shared boundary; unrelated business/UI fixes can continue without moving its authoritative files. The coordinator maintains dependency/result evidence in DPF, not private chat alone. A blocker names one accountable role, exact failed boundary, existing repair and supported next action. Stop recursive blocker expansion at the repository recovery contract's boundary; do not invent another approval or replacement request to hide an unresolved one.

## P5–P6: release and owner proof

Proposed qualification: 20 consecutive complete controlled journeys spanning both entry adapters and the fault matrix; zero duplicate effects, false completion or routine owner technical rescue. Measure acknowledgment/completion p50/p95, recovery time, queue delay and actual cost. Then observe seven days of real authorized work with explicit reports of orphan/unknown/failed results. Targets are design proposals, not already measured production guarantees.

Deployment proof first checks that served bytes contain the qualified fix. Exercise the normal supported owner controls and actual native developer tools; a direct DB write cannot repair the test. Keep source, integration, protected delivery, runtime and owner evidence distinct. The normal closure policy still governs individual BIs; a merged source repair is not extrapolated into operator-company/MSP readiness.

Rollback pauses new admissions or restores the prior supported adapter through its governed rollout seam, retaining in-flight identities, effects, receipts and history. No budget reset, grant expansion, production data edits or blind old-path retry. Before legacy deletion, prove no required producer/consumer remains and keep a read-only compatibility projection for retained records. Do not delete fallback source while real operator flows still depend on it.
