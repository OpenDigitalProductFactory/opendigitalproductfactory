## Acceptance (verbatim BI body criteria)

The six criteria below are requirements AC-1 through AC-6, in order:

- Define the evaluated unit and explicit operator action before writing: a response-producing attempt, not every route in a shared message or fallback chain.
- Resolve exact attempt identity server-side and recheck current thread/room ownership and provider/model/trace association. Read-only platform access alone is not feedback-write authority.
- Record attributable feedback and time through the existing governed/audited path; allow correction according to the chosen design. Preserve missing/ambiguous/historical evidence as unavailable.
- Show feedback coverage separately from execution success, evaluator scores, diagnostics/test results and costs. Do not infer a model score from gratitude, elapsed time, today's provider profile or one shared trace.
- Saving feedback must not dispatch inference, update learned routing behavior or confirm an override.
- Verify ownership/permission removal, repeated attempts/fallbacks, duplicate/corrected submissions, source attribution, and the actual compact keyboard-accessible UX.

## Boundaries and contracts

CONTRACT-PRODUCER is the dedicated feedback design’s producer-binding contract: one existing telemetry id per actual provider call, exact successful producer through the real result types, saved content digest and explicit persisted known-unroomed/Workroom scope. Missing identity/scope or later content change is ineligible. Recover earlier drafts with their producer; rewritten/synthetic/async-start results remain unbound unless their actual producer is carried.

CONTRACT-FEEDBACK is the same spec's governed writer: current state on AdapterRunTelemetry, canonical Principal/source, feedback revision, Serializable current authority and binding checks, atomic AdminActivity, distinct human/agent provenance and protected human judgment. Proposed concrete schema names are responseAttemptId/responseContentDigest/responseScope/responseWorkroomId on AgentMessage, feedbackPrincipalId/feedbackSource/feedbackRevision on AdapterRunTelemetry; use typed enums and existing Principal/Workroom relations. The responseAttemptId remains a deliberately soft telemetry reference; all other durable relationships follow the existing FK/index rules. The implementation may refine names consistently without changing meaning.

CONTRACT-PARITY is one domain writer/read model through authenticated server actions, bounded get_response_feedback / record_response_feedback tools in existing work-thread pack, thread_read/thread_write grants, and existing authorized-surface registry/compiler. Actor/source is server-derived. No helper with optional authorization delegation may be reused.

CONTRACT-UX is compact Kept / Needs revision plus saved/error/correct/clear, real button pressed state, 44px targets and status announcement without focus movement. Existing routing evaluation reports feedback cohorts separately from quality and execution/cost. No automatic provider probes, policy edits or learning weights. Build Studio quality-ledger attribution BI-B93E9C6E and future architect-WSID BI-4538254D are not delivered by this item.

Flows: FLOW-ANSWER is provider call → fallback winner → agentic saved answer → exact eligible response; FLOW-FEEDBACK is read current state → authorize → explicit choice/correction/clear → atomic audit → reload; FLOW-ROUTING is scoped routing evaluation → separate human/agent/unavailable counts → exact authorized saved-answer review in the same inspector → contextual feedback, retaining navigation and current filters. CONTRACT-ANSWER-READ is the separate opt-in answer DTO/read seam described in the canonical design; routine state and general routing projections carry no answer text.

## Risks, failure and rollback

The main risks are wrong producer after fallback/rewrite, lost response on telemetry failure, stale room/owner access, AI judgment presented as human calibration, concurrent edits and a double writer. Tests target each. Nullable additive columns preserve old rows. Keep telemetry retention at its declared window; soft producer pointers resolving to missing rows become unavailable. Roll back application behavior without dropping captured audit history or attributing legacy state; schema rollback requires an explicit reviewed migration rather than destructive column deletion. An infrastructure failure remains unrun/inconclusive, never a product pass. Unknown feedback-write outcome is reconciled by current state before retry.
