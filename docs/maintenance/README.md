# Documentation maintenance

Automated, deterministic signals that keep the docs from rotting — the detection
half of the documentation-freshness epic (EP-1155CEF3).

## [staleness-report.md](staleness-report.md)

A generated list of **stale-candidate docs**: live docs that reference a repo file
committed *more recently* than the doc itself. The doc points at code or a spec that
has since moved on while the doc stood still.

- **Generated by** `scripts/build-docs-staleness.mjs` — do not edit by hand.
- **Refreshed** weekly by `.github/workflows/refresh-docs-staleness.yml`, which opens
  a PR when the report changes. The PR diff is the surface: reviewing what newly went
  stale is the human/agent **verdict** step.
- **A candidate is not a verdict.** It is a deterministic signal that *something the
  doc references changed* — a reviewer confirms whether the doc's wording actually
  needs updating. A doc + its target edited in the same PR share a commit timestamp
  and are never flagged.

### How this fits the anti-drift system

| Concern | Mechanism | Kind |
| --- | --- | --- |
| Dead reference (link no longer resolves) | `Doc Reference Integrity` CI gate (`check-doc-reference-integrity.mjs`) | hard gate, blocks PRs |
| Semantic staleness (link resolves, words are stale) | this report + weekly PR | advisory signal, human/agent verdict |

The gate is the floor; the staleness report is the sweep. Neither can do the other's
job — a link-checker can't read intent, and an intent-reviewer shouldn't be re-run by
hand on every route rename.

## [gate-cost-inventory-2026-11.md](gate-cost-inventory-2026-11.md)

A point-in-time, evidence-based inventory of every check that can block a change from merging, covering required
GitHub checks, local guards, hooks, readiness gates, manifests and reviewer token caps. Each gate is classified by
risk, with its measured cost and frequency and a ranked keep / demote / auto-fix / retire recommendation. It is
analysis only and changes no gate (BI-CF5ECBF6).
