## One implementation

The component repository owns portable advisory scoring, option identities,
uncertainty, decision-scope vocabulary and bounded trusted JSON. DPF owns its
callers and compatibility paths. The real option-recommendation and
principle-decide entry points import the package directly. The nine retired
validator paths forward the package exports without a second implementation.

[The receiving inventory](../../packages/validators/vendor/JUDGMENT-ADOPTION.json)
records each bridge's caller set, accountable owner, tracking item and removal
condition. Remove a bridge after its production and isolated consumers have
migrated and their loader parity is verified. A test-only caller does not justify
keeping it indefinitely. Keep Apache notices and source provenance with the
artifact. Never patch the archive or a receiving copy to fix shared semantics;
qualify a new immutable component candidate and update the coupled receiver.

Public `import` and `require` conditions select the same synchronous ESM files.
This supports the existing framework source loader while preserving function
and value identity across loaders. The package does not ship a second compiled
CommonJS implementation. The root, web and validators declarations resolve the
same exact archive; the isolated mobile lock has its own explicit file mapping.
Existing image contexts carry the vendor directory before frozen installation.

## Dependency-free safety-check distribution

The golden decision guard still runs without application source, installed
application packages, TypeScript or a registry connection. Its committed files
are generated by `scripts/build-judgment-guard-runtime.mjs` from the approved
archive's two emitted scorer files. The builder verifies archive integrity,
regular bounded tar entries, emitted file hashes and the exact relative import
closure. It copies the emitted code, adds a provenance header and records the
archive, component revision, canonical source hashes, builder hash and outputs
in the generated manifest. Do not edit generated JavaScript by hand.

Changing the candidate or generator requires regenerated artifacts, freshness
and hostile-input checks, canonical result/serialization parity and execution
on the supported Node20 guard runtime. Package qualification on Node24 alone
does not prove the guard runtime. Independent installed examples admit only the
reviewed dependency-free foundations and verify exact bytes before installation.

## Host authority and rollback

DPF retains WWMD, WWWD and WSID corpus ownership, authenticated actors, current
admission and revocation checks, persisted records and transactional effect
custody. Advisory output never grants permission. No data migration, new
service, credential change or deployment is part of this receiving refactor.

Rollback restores the prior dependency declarations, root/mobile locks, caller
imports, compatibility bodies and generated distribution together through a
protected source revert. It does not rewrite decision history or independently
roll back other component consumers. GPP receiving adoption is a separate slice
(BI-2D3F986C); DPF2 owns its actual adapter, host enforcement and acceptance.
