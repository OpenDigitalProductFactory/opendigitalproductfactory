## Rule

**Limit work in progress (WIP)** to improve **flow** — the smooth, predictable movement of work from start to finish. Favor finishing work over starting new work.

## Why

Limiting WIP "reduces context-switching and pulls focus toward completion." Too much in progress means everything is started and nothing is done; flow stalls and lead times balloon. Managing flow means **surfacing bottlenecks** so the team can address them.

Track the **four flow metrics**: WIP, cycle time, work-item age, and throughput. The Kanban-for-Scrum practices — visualize the workflow, actively manage WIP, measure flow, and run feedback loops — operationalize this. SAFe's "make value flow without interruptions" aligns.

## How To Apply

1. **Set explicit WIP limits** per workflow stage.
2. **Pull, don't push** — start new work only when capacity frees.
3. **Watch work-item age** — aging items are the early signal of a stalled flow.
4. **Forecast from throughput** — see [[professions/scrum-master/velocity-and-forecasting]].
